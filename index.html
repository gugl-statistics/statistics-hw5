1Ex. 1 - Riemann and Lebesgue integration

Two ways of adding up the area under a curve.

Riemann: split the domain

Cut [a, b] into N subintervals of width h = (b − a)/N, take the value of f at one point (the "tag") in each, and add up the rectangles:

RN = Σi f(ξi)·h

f is Riemann integrable if the upper and lower (Darboux) sums have the same limit, i.e. the result doesn't depend on the tags. In the code I use the midpoint of each subinterval as the tag.

Lebesgue: split the range

Cut the set of values into levels 0 = t0 < t1 < … < tM, look at the preimage Ej = {x : tj ≤ f(x) < tj+1} of each band, and weight each level by the measure (total length) of its preimage:

LM = Σj tj·μ(Ej)

This is the integral of a simple function below f; the Lebesgue integral is the sup over all of them.

The usual comparison is counting coins: Riemann goes through the coins in the order they are on the table and adds their values, Lebesgue first sorts them by value and then counts how many there are of each kind. The second way doesn't care about the order of the points, only about "how much" of the domain has a given value.

How I made the Lebesgue idea numerical

Rearranging the sum by bands gives the "layer cake" formula, which for f ≥ 0 is exactly the Lebesgue integral:

∫ f dμ = ∫0∞ μ({x : f(x) > t}) dt ≈ Σj (tj+1 − tj)·μ({f > tj*})

So the only real work is computing the measure of a preimage {f > t}. My algorithm:

  1. Evaluate f once on a grid of K = 1,000 points, to find the range and to see roughly where f crosses each level t.
  2. For every level t and every pair of grid points where f − t changes sign, find the crossing point with 55 steps of bisection (this gets it to machine precision, also for jumps).
  3. The preimage {f > t} is then a union of intervals between crossings, and its measure is the sum of their lengths.
  4. Use the middle of each band as tj* (the classical lower sum uses the top of the band and converges much more slowly, see the table in 1.3).

For the unbounded function 1/√x I used M/2 equal bands up to f = 10 and M/2 geometric bands from 10 to 10¹², since the levels can go up to infinity; the part above 10¹² contributes only ∫10¹²∞ t−2 dt = 10−12. All the functions in the list are ≥ 0; for a function with negative parts one would integrate f⁺ and f⁻ separately.

Do the two approaches converge to the same value?

Yes, for every function in the list. All the columns in the summary approach the exact value, and the differences between Riemann and Lebesgue go to zero as N grows. This is what theory says: if f is Riemann integrable on [a, b], it is also Lebesgue integrable and the two integrals are equal. For 1/√x the Riemann integral exists only as an improper integral (limit of ∫ from ε to 1), but it still converges to 2, just slowly.

Where they behave differently

  • Smooth functions (sin, x², sin x/x): Riemann wins. The midpoint rule has error O(1/N²): for sin it goes from 8.2·10⁻⁷ at N = 1,001 to 8.2·10⁻⁹ at N = 10,001. The Lebesgue version converges more slowly, about O(M−1.5) (5.4·10⁻⁶ to 1.7·10⁻⁷). The reason is interesting: where f is flat (the top of sin, x² near 0) the measure of {f > t} changes very fast with t (for sin near the top it behaves like √(1 − t)), so the band midpoint rule loses accuracy there. Riemann has the opposite problem: it struggles where f is steep. It's like the two methods are "dual" to each other.
  • Jumps: Lebesgue wins. For the 0/1 step the Riemann sum is off by about h/2 (error 5·10⁻⁴ at N = 1,001, O(1/N)), because one strip contains the jump. The Lebesgue sum is exact for any number of bands: the bisection finds the jump at 0.5 exactly, so every preimage {f > t} = [0, 0.5) has the right length. For the 1/3 step Lebesgue is also O(1/M), but only because one band straddles the value 1; with levels at the values of the function, {0, 1, 3}, two bands give the exact answer.
  • The kink |x − 0.5|: Riemann is O(1/N²) (2.5·10⁻⁷ at N = 1,001) because only the strip with the kink is wrong. Lebesgue is exact (up to rounding) since μ({f > t}) = 1 − 2t is a straight line in t, and the midpoint rule integrates straight lines exactly.
  • The unbounded 1/√x: Lebesgue wins by far. Riemann converges like 1/√N (1.9·10⁻² at N = 1,001, 6.0·10⁻³ at N = 10,001: ×10 strips only gives ×3.16), because the first strip misses most of the spike. For Lebesgue the function being unbounded is not a problem at all: μ({f > t}) = min(1, 1/t²) has finite area, and with 10,001 bands the error is 9.6·10⁻⁷.
  • Efficiency: Riemann is much cheaper. Riemann needs N evaluations. My Lebesgue version needs the 1,001 grid points plus 55 bisection steps for each crossing of each band, so 37 to 110 times more evaluations (1.1 million for sin with 10,001 bands) and about 300 times more time (0.5 s vs 1.5 ms). Per evaluation Riemann is better on smooth functions, Lebesgue is better on jumps and on 1/√x.

The real reason Lebesgue is expensive is that it needs the preimages, i.e. it has to solve f(x) = t, which numerically means root finding. When the preimages are known exactly (like for monotone functions that can be inverted), it becomes very cheap. In one dimension, for normal functions, Riemann-type rules (midpoint, trapezoid, Simpson) are the practical choice; the strength of Lebesgue is more theoretical (limits, convergence theorems, very irregular functions).

1.4The pathological functions

Where the two definitions really disagree.

Dirichlet function: f = 1 on rationals, 0 on irrationals

Try it
  • Riemann: every subinterval contains both rational and irrational points, so the upper Darboux sum is always 1 and the lower is always 0. With rational tags the Riemann sum is 1, with irrational tags it's 0, for every N. The limit depends on the tags, so the Dirichlet function is not Riemann integrable.
  • Lebesgue: there are only two levels. The preimage of 1 is ℚ ∩ [0, 1], which is countable, so it has measure 0: list the rationals as q1, q2, … and cover qk with an interval of length ε/2k; the total length is at most ε for every ε > 0. So ∫ f dμ = 1·μ(ℚ ∩ [0,1]) + 0·μ(irrationals) = 1·0 + 0·1 = 0.
  • A numerical problem: on a computer every floating point number is m/2k, i.e. rational. A naive implementation would say f = 1 everywhere and integrate to 1. This function cannot even be represented with doubles, so for the demo I treat the tags symbolically (I know which ones are rational by construction).

Thomae's function: f(p/q) = 1/q in lowest terms, 0 on irrationals

Thomae's function (points p/q with q ≤ 60)
Try it

This one is Riemann integrable even though it is discontinuous at every rational point: it's continuous at the irrationals, and the set of discontinuities (the rationals) has measure zero, which is exactly Lebesgue's criterion for Riemann integrability. I computed the sums with exact fractions (Python Fraction):

The upper Darboux sum needs the largest value of f in each strip, i.e. the fraction with the smallest denominator in [i/N, (i+1)/N]; I found it with a search on the Stern-Brocot tree. All the sums go to 0, but slowly (the upper sum is still 0.011 at N = 10,000). The lower sums are always 0 and so are the sums with irrational tags.

The Lebesgue version is immediate: for every t > 0 the set {f > t} = {p/q : q < 1/t} is finite (for t = 0.01 it has 3,005 points, for t = 0.001 it has 303,793 points), so its measure is 0, so every band contributes 0 and the integral is exactly 0 with any number of bands. Both definitions agree (0), but Lebesgue gets there with no approximation at all.

One more: the indicator of a "fat" Cantor set

The Smith-Volterra-Cantor set is built like the Cantor set but removing smaller and smaller middle pieces (1/4, then 1/16 from each of the 2 remaining pieces, …), so what is left is closed, contains no interval, and still has measure 1/2. Its indicator function is discontinuous at every point of the set, which has positive measure, so it is not Riemann integrable: the lower Darboux sums are 0 (every strip contains a gap) and the upper sums tend to 1/2. The Lebesgue integral exists and is 1·(1/2) = 1/2. This is a "nicer" example than Dirichlet, because the function is not crazy everywhere, it's just the indicator of a strange set.

1.5Conclusions for Ex. 1

  • For all the Riemann-integrable functions both numerical approaches converge to the same value, as the theory says.
  • Riemann (midpoint) is cheaper and more accurate for smooth functions; my Lebesgue version is better for jumps, kinks and especially the unbounded 1/√x, but it costs 37 to 110 times more function evaluations because of the root finding needed for the preimages.
  • The real difference shows up with the pathological functions: Dirichlet is not Riemann integrable but has Lebesgue integral 0; Thomae is integrable in both senses (integral 0) but Lebesgue gets it exactly and immediately; the fat Cantor indicator is not Riemann integrable but has Lebesgue integral 1/2.

2Ex. 2 - Numerical computation of the normal CDF

Why there is no formula, and what to do instead.

We want

Φ(z) = P(Z ≤ z) = ∫−∞z (1/√(2π)) e−t²/2 dt

The density is continuous, so by the fundamental theorem of calculus Φ is an antiderivative of it, and it certainly exists. The point is that it can't be written with elementary functions: those obtained from x and constants with +, −, ×, ÷, roots, exp, log, and compositions of these (trigonometric functions are included, since they can be written with complex exp and log). The notes linked in the assignment (Gardner's notes on Hogg, McKean and Craig, Section 3.4) make exactly this correction to the textbook, which says that the integrand "does not have an antiderivative": it has one, just not an elementary one.

Liouville's theorem

Liouville proved in the 19th century that ∫ex²dx is not elementary; the modern algebraic version is explained in Rosenlicht's paper "Integration in finite terms" (American Mathematical Monthly, 1972). The form that is useful here is a consequence of the general theorem:

Theorem (Liouville). Let f(x) and g(x) be rational functions, with g not constant. Then ∫ f(x)·eg(x) dx is an elementary function if and only if there is a rational function R(x) such that

f = R′ + R·g′

and in that case ∫ f eg dx = R·eg + C.

The "if" part is easy (differentiate R eg). The deep part is the "only if": the theorem says that if the integral is elementary at all, it must have this very simple shape.

Applying it to e−x²/2

Here f = 1 and g = −x²/2, so g′ = −x and we would need a rational R with

R′(x) − x·R(x) = 1

  1. R can't have a pole. If R had a pole of order k ≥ 1 at some point a (possibly complex), then R′ would have a pole of order k + 1 at a, while x·R has a pole of order at most k there. So R′ − xR would still have a pole at a, but the right side is the constant 1. Contradiction.
  2. So R is a polynomial, and that doesn't work either. If R = 0 the left side is 0 ≠ 1. If R has degree d ≥ 0, then x·R has degree d + 1 and R′ has degree d − 1, so the left side has degree d + 1 ≥ 1 and can't be the constant 1.

No such R exists, so ∫e−x²/2dx is not elementary. And Φ can't be elementary either: if it were, √(2π)·Φ would be an elementary antiderivative of e−x²/2. The same argument with g = x² shows the classical case ∫ex²dx.

2.2The error function

Giving the integral a name.

Since the integral can't be expressed with the functions we already have, we define a new one:

erf(x) = (2/√π) ∫0x e−s² ds,    erfc(x) = 1 − erf(x)

With the substitution t = √2·s in the definition of Φ:

Φ(z) = ½ [1 + erf(z/√2)] = ½ erfc(−z/√2)

This is an exact analytical representation, in the same sense that ln x is "exact" even though it is defined as ∫1x dt/t: once erf is accepted as a special function with known properties (odd, erf(∞) = 1, derivative (2/√π)e−x², series, asymptotic expansion…), Φ is a closed formula in terms of it. Also general normal variables are covered: P(X ≤ x) = Φ((x − μ)/σ) for X ~ N(μ, σ²), and Φ(−z) = 1 − Φ(z).

But it doesn't compute anything by itself. erf is just a name for the integral: to get the number erf(0.7) someone still has to evaluate it with a numerical method (a series, a continued fraction, a rational approximation…). This is also true for exp, sin or log, but those are built into every language, and erf often isn't: for example JavaScript's Math object has exp, log, sin, but no erf, so on this page every method is written by hand.

Integration rules

Integrating the density from 0 to z works fine and converges as expected: at z = 1.96, Simpson goes from 3.1·10⁻³ with 2 panels to 2.1·10⁻⁶ with 8 and 7·10⁻¹⁵ with 1,024 (×2 panels → error ÷16), the trapezoid from 9.0·10⁻³ to 3.5·10⁻⁸ (×2 → ÷4). The problem is cost (hundreds of exponentials for every value) and the lower tail: for z = −8 the answer is 6·10⁻¹⁶ but the rule computes it as ½ minus a number very close to ½, so it gets only the absolute error right.

The power series and its trap

The series converges for every z (it's an alternating series, and once the terms start decreasing the error is at most the first omitted term). For small z it's great: 11 terms at z = 0.5, 24 terms at z = 2, error ~10⁻¹⁶. But for large z the terms first grow a lot before decreasing: the biggest term is about ez²/2-sized, while the result is between 0 and 1. With 16 significant digits, all the digits are lost in the cancellation:

At z = 10 the series says Φ(10) ≈ 418, which is not even a probability. So the series alone is fine only up to |z| ≈ 3 or 4.

The continued fraction for the tail

For the tail I used the classical continued fraction of the Mills ratio, Q(x)/φ(x) = 1/(x + 1/(x + 2/(x + 3/(x + …)))), evaluated from the bottom up with a fixed depth n. It converges faster the larger x is, which is exactly the opposite of the series:

I used the depth n = 10 + 400/x², which is a bit more than needed everywhere. So the final method is: the series for |z| ≤ 2.5 (at most ~30 terms), the continued fraction beyond (at most 74 levels, and only 14 at |z| = 10). For negative z the tail is computed directly, so Φ(−8) = 6.2·10⁻¹⁶ comes out with full relative precision instead of as a difference of two numbers close to ½.

2.4Accuracy

Against a 40-digit reference and against values from the web.

As the "exact" value I used Python's mpmath library with 40 to 50 significant digits. All errors below are computed against it on the grid z = −10, −9.95, …, 10.

  • A&S 26.2.17 is good to 7.4·10⁻⁸ in absolute terms, as advertised, but its relative error in the tail is bad (2% at z = −10), so it's fine for a z-table and not for tiny p-values.
  • The power series and the integration rules are accurate in the middle but completely wrong in the far tail (relative errors above 1).
  • My method has a max absolute error of 4·10⁻¹⁶ and a max relative error of 5.9·10⁻¹⁴ in the lower tail, close to the C library (math.erfc, 1.2·10⁻¹⁴). The worst point is z = −2.5, right where the series stops: Φ(−2.5) = 0.0062 is obtained as ½ minus the series, which loses about 2 digits. Moving the switch lower would fix it, at the cost of a longer continued fraction.

Comparison with values found on the web

I used the standard normal table on Wikipedia (5 decimals for Φ, 6 significant digits for the far tail 1 − Φ(z) at integer z) and the "68-95-99.7 rule" page, which gives P(|Z| < 0.5) = 0.382924922548026 and P(|Z| < 1) = 0.682689492137086 with 15 digits, i.e. Φ(z) = (1 + P)/2.

Every value agrees with the web to all the digits printed there. The two 15-digit values match my method to the last digit, and the tail values down to 6.22·10⁻¹⁶ at z = 8 match to 6 significant digits.

2.5Efficiency

Time per evaluation.

Try it

Times 200,000 evaluations of each method in the browser, at random z in [−6, 6].

  • The integration rules are the slowest because they evaluate the density (an exponential) about 100 times per value, and they are still not very accurate.
  • The series needs up to ~30 terms in its range and a couple of hundred outside it (where it's wrong anyway).
  • A&S is the fastest pure implementation (one exponential and a degree-5 polynomial) but only to ~7 digits.
  • Mine is about 2.5 times faster than the series in Python and gives full precision. It is still slower than the C library, which is compiled and uses rational approximations (a fixed number of operations, no loops), but in the browser it takes around a tenth of a microsecond per value, which is more than enough.

2.6Conclusions for Ex. 2

  • Φ has an antiderivative but not an elementary one: by Liouville's theorem, ∫e−x²/2 would have to be R·e−x²/2 with R′ − xR = 1, and no rational R does that.
  • erf gives Φ(z) = ½[1 + erf(z/√2)], an exact formula, but erf is defined by the same integral, so its values still need a numerical method.
  • Integration rules and the power series work in the centre but fail in the tails because of cancellation; A&S is fast but limited to ~7 digits; the continued fraction is very good in the tails and bad near 0. Combining the series (|z| ≤ 2.5) with the continued fraction (|z| > 2.5) gives near machine precision everywhere, agrees with the web tables to every printed digit, and is fast.

A small note on the notes: on page 6 the standardization is written z = (x − μ)/σ², it should be (x − μ)/σ, and the exponent in the definition of Φ is written −t/2 instead of −t²/2.
